# UI Design

把 UI 当作可检验的视觉系统：先让用户看懂内容、识别关系、找到下一步，再打磨质感。结果使用用户的语言。

用户给出页面、截图、代码或设计要求时直接使用；没有参数时，使用当前对话中最近且相关的界面。已有品牌、设计系统、目标密度和技术栈优先于本 skill 的默认建议。

## 按任务选择交付

- **设计新界面**：从主要任务与真实内容出发，建立风格、布局和组件层级，交付用户要求的方案、原型或实现。
- **优化现有界面**：先观察实际界面及已有样式，保留任务、内容与交互，针对最影响理解和操作的问题修改。用户要求代码时完成实现，不停留在建议。
- **视觉审查**：结合可见证据定位问题，按用户影响排序，说明具体位置、影响与改法；审查本身不扩展成代码重写。

## 工作流程

### 1. 明确任务与风格

从上下文确认目标用户、主要操作、内容类型、使用设备及必须保留的约束。仅在缺失信息会改变关键设计时提问；其余采用合理假设并简短说明。

先定一个一致的个性，例如稳重专业、友好轻快或简约克制，把它落实到字体、色彩、圆角和措辞，避免不同组件各自表达不同风格。色彩与字体的情绪联想是判断线索，不能代替用户、品牌和文化背景。

复用已有设计 token 和组件。没有设计系统时，只定义当前任务需要的文字层级、间距、内容宽度、圆角、表面和语义颜色，避免为单页先造一套完整组件库。

### 2. 先建立灰度骨架

新设计先用中性色、间距、字重与尺寸建立主次；已有界面可做灰度检查，不必重做一份灰度产物。去掉品牌色后，主要内容、分组和操作仍应能被识别。

明确每个任务区域的主要、次要与辅助操作。重点不突出时，先弱化竞争元素；不要只放大标题、缩小辅助文字或给所有按钮加高饱和填充。

按内容约束宽度，组间距大于组内距。可先给足空间，再结合整页观感和信息密度逐步收紧。

### 3. 按问题应用设计规则

需要具体改法或检查细节时，阅读 [二十条设计规则](references/design-rules.md) 中相关部分；全面审查时覆盖全部适用规则：

| 当前问题 | 对应规则 |
| --- | --- |
| 风格不一致、过早纠结装饰 | 01–02：个性与灰度起步 |
| 主次混乱、字段或按钮互相抢戏 | 03–06：文字、弱化、标签与操作层级 |
| 拥挤、过宽、归属不清、移动端比例失衡 | 07–10：留白、宽度、亲疏与响应式 |
| 阅读费力、混合字号对不齐 | 11–12：行长、行高与基线 |
| 色彩刺眼、状态难辨、对比不足 | 13–15：色阶、对比与多通道表达 |
| 缺少焦点、图片压字、素材比例不自然 | 16–18：强调边框、图片反差与素材尺寸 |
| 线条过多、首次使用无从下手 | 19–20：分隔与空状态 |

先修正可读性和状态识别，再修正层级与归属，最后打磨装饰。按用户任务选择规则，不把二十条逐项套到每个组件。

### 4. 覆盖真实内容和状态

用户生成内容的功能，优先设计首次使用的空状态：说明这里会出现什么、下一步做什么，并提供明确可执行的操作。仅隐藏当前确实无用的控件。

区分首次无数据、筛选无结果和加载失败；无结果时保留能清除条件的筛选入口。不要让空状态掩盖错误或仍在加载的情况。

空状态图形要与原因和下一步动作一致，避免把创建用的加号复用于筛选无结果等不同含义；没有合适图形时，清晰文案与操作即可。

响应式按元素角色分别调整字号、间距、列数和宽度，避免整页等比缩小。用真实长标题、长文本、数字及实际语言检查换行；不要靠删掉必要信息来换取整洁。

高密度列表的小屏布局要兼顾跨记录扫描：按任务选择局部可滚动表格或紧凑记录布局，避免默认改成每个字段独占一行的大卡片。具体判断见参考规则 07、10。

### 5. 验证并收敛

有可用预览工具时查看实际渲染，检查目标桌面与小屏、相关内容状态及主要操作。先看整页焦点，再看局部细节；代码中的数值不能代替视觉判断。

密集数据界面用相同数据量检查每屏记录数、重复标签、行高及查找关键字段所需的滚动，结合阅读和触控判断是否应收紧。页面变短不能以删字段、缩小可读文字或压缩操作目标为代价。

实测文字与实际背景的对比度，普通文本以至少 4.5:1 为底线；浅底深字、半透明蒙版和柔和阴影都不自动保证达标。状态除了颜色还应有文字、符号或形状线索。视觉弱化不能牺牲可读性，也不能删除表单标签、焦点提示或必要的交互边界。

无法渲染或测量时，明确哪些结论来自静态检查、哪些仍未验证，不宣称完成了视觉或无障碍验证。

交付时简短说明关键修改及其用户收益，附结果入口和实际验证情况。设计方案给出可落地的视觉参数；审查建议写成“具体问题 → 用户影响 → 调整方式”，避免只有“更高级”“更好看”等结论。

## 判断边界

这些规则是决策工具，不是统一风格模板。文章中的字号、色阶数量、容器宽度和行高均为起点，应根据字体、语言、屏幕、内容密度和品牌调整。为清晰检索保留数据标签，为高密度工作合理收紧留白，为必要分隔保留边框。

本 skill 提炼自用户提供的《当写代码不再是门槛，UI 成了做产品最大的痛点》文章及其对《Refactoring UI》的归纳；不将文章的示例当作原著完整内容或已验证的标准。
